# 审美图采集助手

<p align="center">
  <strong>v2.0.0</strong><br>
  面向视觉参考素材的本地优先 Chrome 图片、GIF 与视频采集扩展
</p>

<p align="center">
  <strong>中文说明</strong> · <a href="README.md">English</a>
</p>

支持花瓣、Pinterest、站酷、小红书和 Behance。你可以在不同页面、不同平台持续选择素材，将它们累积到同一个本地待下载队列中，统一去重并批量导出；队列、登录凭据和采集内容不会上传到项目方服务器。

> 本仓库只包含扩展源码，不包含账号凭据、浏览器 Profile、已采集媒体或私密画板数据。

## 支持的平台

| 平台 | 支持页面 | 支持内容 |
| --- | --- | --- |
| 花瓣 | 画板、搜索结果、Pin 详情和推荐流 | 图片 |
| Pinterest | 首页、搜索、画板和 Pin 相关推荐 | 图片 |
| 站酷 | 作品详情页 | 正文图片、GIF 和支持的视频 |
| 小红书 | 笔记详情与轮播 | 图片、普通视频、逐页 Live／实况照片 MP4 |
| Behance | 项目详情页 | 项目图片、原始 GIF、Vimeo 视频流 |

第三方平台的页面结构与媒体接口可能变化。如果插件没有识别当前页面，请先进入实际的画板、Pin、笔记、作品或项目详情页再尝试。

## 主要能力

- 使用 Chrome Manifest V3，点击扩展图标打开常驻右侧栏。
- 在支持页面显示逐项选框，可单独选择或取消素材。
- 使用 `chrome.storage.local` 保存跨页面、跨平台待下载队列。
- 同时检查当前队列与本地下载历史，减少重复采集。
- 混合处理图片、GIF 和视频，并在支持时保留动画或原视频格式。
- 六路有限并发，显示实时进度，支持停止、继续和失败项保留。
- 花瓣页面支持智能过滤信号，同时保留人工选择能力。
- 通过 Chrome 下载接口进行本地 ZIP 或批量保存。
- 不使用远程统计后端、云端队列或内置账号凭据。

## 源码安装

1. 下载或克隆本仓库。
2. 在桌面版 Chrome 打开 `chrome://extensions/`。
3. 开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的目录。
5. 可按需固定扩展；点击扩展图标即可打开右侧栏。
6. 遇到需要登录的内容时，请使用你自己的账号登录对应平台。

使用新版本文件覆盖旧版后，请回到 `chrome://extensions/`，点击扩展卡片上的“重新加载”。

## 基本使用流程

1. 打开受支持的内容页面。
2. 通过页面选框选择或取消图片、GIF 或视频。
3. 点击“加入待下载”或当前页面对应的采集按钮。
4. 继续浏览其他页面或平台，新的素材会持续累积。
5. 在右侧栏检查待下载数量和历史去重统计。
6. 开始下载或打包；中途可以停止，之后继续处理未完成部分。

“清空待下载”只清除当前队列，仍保留下载历史用于后续去重；“完全重置”会连同本地去重历史一起清除。

## 平台专项说明

### 小红书 Live／实况照片

- 每个支持的轮播页分别绑定真实视频流，不把多页 Live 合并成一个备用链。
- 识别到 Live 后排除静态 WebP 封面，避免把封面误当作最终素材。
- 页面使用 `blob:` 播放时，可从浏览器近期加载的媒体资源中恢复真实 MP4。
- v1.8.10 有意采用 v1.8.8 的选框显示逻辑，以规避 v1.8.9 引入的视觉回归。

### Behance Vimeo

- Vimeo 地址可能过期或随会话变化，因此在实际下载时实时解析。
- 播放器开放渐进式 MP4 时优先选择最高画质版本。
- 只有 HLS 时，选择最高带宽变体并合并 fMP4 分片。
- 视频流无法获取或下载失败时，任务会保留在失败／待处理流程中并显示原因，方便重试。

## 隐私与权限

插件只在本地 Chrome 中运行，没有项目方运营的远程后端。

| 权限 | 用途 |
| --- | --- |
| `activeTab` | 与当前正在使用的受支持页面通信。 |
| `storage` | 在本地保存队列、设置、任务进度和去重历史。 |
| `downloads` | 通过 Chrome 保存 ZIP 或媒体文件。 |
| `sidePanel` | 显示常驻采集界面。 |
| 站点域名权限 | 在五个支持平台及其媒体 CDN 上识别并请求运行时资源。 |

插件没有申请 Chrome 的 `cookies` 权限。需要登录的请求只在运行时使用当前浏览器会话；Cookie 不会被导出，也不会写入本仓库。数据流说明见 [docs/PRIVACY.md](docs/PRIVACY.md)。

## 开发与验证

需要 Node.js 18 或更高版本，不需要安装第三方 npm 依赖。

```bash
npm run verify
```

也可以直接运行：

```bash
node scripts/verify.mjs
node --test tests/*.test.mjs
```

验证内容包括 Manifest、域名权限、必需文件、JavaScript 语法、敏感字段、本地队列、GIF 动画、小红书提取与选框逻辑，以及 Vimeo 渐进式 MP4／HLS 解析。

## 架构概览

```text
各平台页面适配器
  -> 页面选框与标准化媒体记录
  -> background.js 持久队列与本地去重
  -> popup.js 右侧栏控制与混合媒体下载
  -> Chrome Downloads / ZIP 输出
```

项目保持轻依赖，浏览器端使用仓库内置的 JSZip 和 `lib/` 媒体工具。

## 已知限制

- 页面选择器和嵌入元数据依赖第三方平台当前结构，平台改版后可能需要更新。
- 带签名的图片或视频地址可能过期，建议采集后尽快完成下载。
- Vimeo 能否下载取决于播放器向当前浏览器会话开放的媒体格式。
- HLS fMP4 合并要求分片兼容且未加密，并需要足够的浏览器内存。
- 大型混合媒体 ZIP 受浏览器可用内存和磁盘空间限制。
- 自动化测试使用 fixture 和模拟环境，平台大改版后仍需进行真实页面验证。
